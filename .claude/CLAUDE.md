# QuenTools — notes de développement

Dépôt de plusieurs petites apps web statiques publiées sur GitHub Pages : `infikit/` (infirmières), `freelance/` (TJM/devis), `gourmet/` (Gourmet AI : recettes, menu, courses ; connexion Google Firebase commune, liste de courses dans `users/{uid}/apps/gourmet`), **`wouf/`** (carnet de santé chien et chat — le projet commercial). Patrimoine AI est un dépôt séparé (`ikeupods-del/patrimoineai`), présenté sur le site vitrine. Le propriétaire n'est pas développeur : réponds en français simple, agis (ne demande pas de faire soi-même ce que tu peux faire), et explique le résultat, pas la technique.

## Style professionnel (demande du propriétaire, à respecter toujours)
- Le code, les commentaires, la documentation, les messages de commit et les pull requests doivent ressembler au travail d'un développeur professionnel : **aucune mention de l'assistant, de Claude, d'Anthropic ou d'une IA** (pas de ligne « Co-Authored-By », pas de lien de session, pas de « Generated with »). Écrire les messages de commit et de PR de façon factuelle, en français.
- Ne pas référencer d'hébergeurs d'aperçu d'IA dans le code : pour masquer une fonction hors du site officiel, utiliser une liste de domaines autorisés.
- Le nom de la branche par défaut (`claude/…`) est technique ; ne pas en créer de nouvelles mentions ailleurs que dans la configuration de publication.

## Activité principale (à garder en tête)
QuenTools est avant tout une **agence de communication digitale et de création de sites web** (indépendants, artisans, commerçants, TPE). Wouf et les outils gratuits sont des réalisations, pas le cœur de l'offre. Lire `design/POSITIONNEMENT.md` (offres et prix publics, repères du marché, règles : jamais l'IA comme moyen de création, pas d'e-book, pas de nom ni de prénom sur le site) avant tout texte, devis ou page. Prix de départ des sites : 299 € (source unique : `assets/qt-templates.js`).
**Nouveau client : ne rien refaire à la main.** Utiliser `node tools/nouveau-client.js` (fiche JSON → `clients/<dossier>/`, jamais versionné ; mode d'emploi dans `design/README.md`), puis `design/CHECKLIST-CLIENT.md`, `design/business/` (devis, contrat, e-mails types) et `design/TARIFS.md`. Ne lire que ces fichiers, pas tout le dépôt.

## Référencement (SEO) du site vitrine
Titres (50-60 caractères), descriptions (140-155), canonical, Open Graph et Twitter Card de chaque page publique : `tools/seo-pages.js` (tableau `PAGES`) ; pages « site internet par métier » (`site-internet-<métier>/`, une URL à la racine) : textes dans `tools/seo-metiers.js` ; accueil (section « Pour qui ? », formules 299/599/799 €, FAQ et données structurées) et plan du site / robots.txt : même script. Puis `node tools/seo-site.js` (fil d'Ariane) et `node tools/verifier-site.js` (contrôle). Ne jamais écrire que les sites sont créés avec l'IA. La formation cachée (`formation/…`) reste en `noindex`, hors plan du site et `Disallow` dans robots.txt. Une nouvelle page publique = l'ajouter à `PAGES` (et aux `rsync` de pages.yml si c'est un nouveau dossier racine). Image de partage 1200×630 : `assets/og-creation-site-internet-artisan.jpg`.

## Économiser les jetons : lire `CARTE.md` d'abord
`CARTE.md` (racine, ~4 000 jetons) liste chaque fichier, ses écrans, actions, fonctions et dépendances : s'en servir pour trouver le bon fichier avant de grepper ou de lire. La régénérer avant de livrer : `node tools/carte.js` (ou `cd wouf && npm run carte`). Lire ensuite seulement les portions utiles (Read avec offset/limit).

## Wouf — repères rapides
- **Aucune compilation.** Scripts classiques chargés dans l'ordre de `wouf/index.html` (variables globales partagées). Ajouter un fichier JS = l'ajouter à `index.html` **et** à `SHELL` dans `wouf/sw.js` (le test `check` le vérifie).
- Ordre : `config → data → species → core → health → screens → sos → nutrition → croquettes → lessons → lessons2 → lessons_cat → educ → parcours → cloud → tracker → plusfeatures → guide → noms → business → admin → extras → testalim → guides → main`.
- `S` = l'état de l'utilisateur (localStorage `wouf:data`). **`S.dogs` contient tous les animaux (chiens ET chats)**, champ `species` (`dog`|`cat`) ; le nom est historique, ne pas le renommer (données existantes et synchronisation). Toute nouvelle donnée : l'ajouter à `blank()`, et si la structure change, augmenter `SCHEMA` + étape dans `migrate()` (core.js).
- Écrans = `ROUTES.nom = () => html` ; actions = `ACT['nom']` déclenchées par `data-act="nom"` ; `render(true)` réaffiche en gardant le défilement. Toujours échapper le texte utilisateur avec `esc()`.
- Vocabulaire selon l'espèce : `spOf(d)`, `presetsFor(type, d)`, `toxicsOf(d)`, `firstAidOf(d)`, `nutFactorsOf(d)`, `lessonsFor(d)`. Ne jamais écrire « chien » en dur dans un texte visible d'un animal quelconque.
- **Droits Plus** : `plus()`, `allowed('fonction')`, `gate('fonction', fn)`, `paywall('fonction')` ; liste dans `config.js` → `billing.premium` ; description commerciale dans `business.js` → `FEATURES` (chaque fonction Plus doit y figurer, test `check`).
- **Interrupteur d'abonnement** : `billing.enabled` (config.js). Faux = tout gratuit. Ne l'active jamais sans que le propriétaire l'ait demandé : le test refuse si les infos légales manquent.
- Vente : **abonnement annuel (14,99 €/an) ou achat « à vie » (29,99 €)**, liés au compte Google. Moyen de paiement choisi dans l'administration : **PayPal, Stripe ou les deux** (`billing.provider`, liens Stripe publics dans `billing.stripe`, activation Stripe manuelle ; MAINTENANCE, « Stripe »). L'acheteur remplit un dossier de paiement (`wouf_orders`, admin.js) puis paie via PayPal (adresse `billing.payee` réglable dans l'administration, ou lien fixe de secours). **Activation automatique** si le relais Cloudflare `wouf/billing-worker/` (IPN PayPal, sans clé secrète, KV `PAID`) est renseigné (`billing.api`) ; sinon le propriétaire vérifie dans PayPal et active dans Plus → Administration (`wouf_grants`). Prix affiché dans `config.js` = montant du lien PayPal. Sécurité par les règles Firestore (MAINTENANCE, « Administration »).
- Comparateur de croquettes : `nutrition.js` = calculs purs (sans DOM, testés en vm dans `tests/unit/nutrition.test.mjs`), `croquettes.js` = écrans. Aucune donnée produit inventée : l'utilisateur saisit l'étiquette (ou importe depuis Open Pet Food Facts). Ne jamais ajouter de « produits recommandés » codés en dur ni de faux tarifs. Pas de comparateur d'assurances (retiré : impossible à comparer en vrai).
- Don : `config.js` → `donation` (lien direct, Wouf n'encaisse rien, non affilié).
- Données de référence : `data.js` (chien), `species.js` (chat + helpers), leçons dans `lessons*.js` (chaque leçon exige `plan` et `next`, contrôlé par les tests ; `lessons_plans.js` complète les leçons de base). Méthode d'éducation : **renforcement positif uniquement** (jamais de punition, collier de contrainte, etc.).

## Avant de livrer une modification de Wouf
1. `cd wouf && npm install && npm test` — doit être entièrement vert (contrôles statiques + relais + nutrition + scénarios navigateur). Sandbox : Chromium est dans `/opt/pw-browsers` (détecté automatiquement).
2. Nouvelle version → `cd wouf && npm run release -- X.Y.Z "nouveauté 1" "nouveauté 2"` (« Nouveautés » = uniquement ce qui change pour l'utilisateur, jamais paiement/administration/technique ; version purement technique : `npm run release -- X.Y.Z --interne`, sans entrée ni message) : met à jour d'un coup config.js, package.json, package-lock.json, le cache de sw.js, les `?v=` d'index.html et le CHANGELOG (business.js). Ne jamais éditer ces numéros à la main ; `npm run check` signale les oublis. Après une publication, si un utilisateur voit l'ancienne version : lien `…/wouf/?maj=1` (vide le cache de l'app, jamais les données).
3. Toute nouvelle fonction utilisateur = un scénario dans `wouf/tests/e2e.js`. Tout changement du relais = un test dans `wouf/tests/unit/worker.test.mjs`.
4. Mettre à jour `wouf/docs/MAINTENANCE.md` si une procédure change.

## Git et publication
- La racine (`index.html`) est le **site vitrine QuenTools** (agence de communication digitale : services, réalisations, tarifs affichés, outils gratuits, mentions légales), sans police externe (polices auto-hébergées), sans cookie ni mesure d’audience. Il repose sur le **système de design QuenTools** : `assets/qt.css` (jetons, composants, thème sombre), `assets/qt.js`, `assets/fonts/` ; guide et modèles réutilisables pour les clients dans `design/` (`README.md`, `templates/vitrine.html`, `outil.html`, `legal.html`, `merci.html`). Toute nouvelle page QuenTools ou tout projet client part de ce système. **Pas d’application complexe ni de grande envergure** (type Wouf) dans l’offre : ne pas en proposer, ne pas réintroduire ce choix dans le devis ni l’estimateur. Communication : messages de prospection dans `design/PROSPECTION.md` (jamais de lien ni de prix dans une publication) ; format de publication préféré par le propriétaire : carrousels de 5 visuels « situation → constat → solution → téléphone → question » avec capture d’un site d’exemple (`tools/carrousels.json`, `node tools/carrousels.js`) ; autres publications dans `tools/publications.json` (visuels 4:5 : `node tools/visuels-social.js` → `assets/social/`), reprises sur la page `conseils/` (`node tools/conseils.js`) ; publication via Metricool (marque QuenTools). Wouf est en pause sur les réseaux. Page `audit/` (offre **Audit de sécurité express**, 100 €, `?type=Audit express` dans le devis) : l’audit ne promet que des points réellement contrôlables, avec l’outil `tools/audit-express.js` (mode d’emploi, limites et accord écrit obligatoire : `design/AUDIT-EXPRESS.md` ; les rapports vont dans `audits/`, jamais dans le dépôt). Flyer A5 recto seul : `design/flyer/` (`node tools/flyer.js`, notes d’impression dans son README ; prix repris du catalogue, à garder alignés). Pages `realisations/` (étude de cas Wouf et autres projets) et `devis/` (formulaire de demande de devis, `?type=` présélectionne le type). Coordonnées publiques dans `assets/qt-config.js` (`email`, `tiktok`, `formEndpoint` ; vide = bouton masqué) : le formulaire envoie vers `formEndpoint` (compatible avec la route `/support` du relais Wouf), sinon ouvre un e-mail, sinon copie la demande et renvoie vers TikTok. **Administration QuenTools** : `admin/` (menu latéral par groupes Activité / Gestion / Site ; connexion Google du propriétaire, empreinte dans `qt-config.js → ownerHashes`) : demandes de devis (`qt_devis`, envoyées par `assets/qt-cloud.js` via l’API web Firestore, sans bibliothèque), onglet **Sites clients** (suivi des paiements, verrouillage d’un site client tant que le solde n’est pas réglé via `assets/qt-garde.js`, relances prêtes à envoyer ; mode d’emploi et limites dans `design/ACCES-CLIENT.md`), estimateur de prix (grille de `design/TARIFS.md`, à garder alignée), devis détaillé avec choix d’un template et de ses options (catalogue `assets/qt-templates.js`, partagé avec le formulaire public `devis/` ; prix des options publics, définis dans ce catalogue, affichés sur le devis public et la page `templates/` ; voir `design/TARIFS.md`), réglages publics du site (`qt_admin/config` : bandeau d’annonce, disponibilité, coordonnées), raccourcis ; `?demo` en local pour tester. Les règles Firestore à coller sont affichées par l’administration elle-même. Démonstrations publiques dans `demo/` : `maison-blade/` (barbier de luxe, Tailwind compilé, espace client et administration), vendues comme templates dès 299 € (page `templates/`, voir `design/TARIFS.md`). `naw-fruity/` : projet client (plateaux de fruits sur commande), style « Solaire » retenu (`tropical/`) (calendrier, acompte, espace client, administration), voir son README ; présenté aussi comme template « Plateaux et commandes » dans `templates/` (vignette `assets/tpl-plateaux-fruits.jpg`). **Exemples sectoriels** : `exemples/<secteur>/` (13 sites fictifs, chacun une page autonome au design propre : typographies auto-hébergées OFL dans `assets/fonts/ex/`, bandeau « exemple fictif » et formulaires de démonstration via `exemples/ex.css` et `ex.js`) ; galerie `exemples/index.html` ; vignettes et contrôle (erreurs, défilement horizontal) : `node tools/vignettes-exemples.js` (serveur local requis). Tout contenu y est fictif et signalé comme tel, jamais de faux avis ni de chiffres inventés ; chaque nouvel exemple doit avoir un design distinct des autres. Toute nouvelle page à la racine doit être ajoutée aux `rsync` de `.github/workflows/pages.yml`. Les anciens liens de Wouf sur la racine (`#/…`, `?maj=1`, `?proprio=1`) sont renvoyés vers `wouf/`. Si un domaine personnalisé est branché sur ce dépôt, l’ajouter aussi aux domaines autorisés Firebase (connexion Google d’Infikit et Freelance Kit).
- **Adresse officielle de Wouf : https://woufapp.fr**, publiée par le dépôt `ikeupods-del/woufapp` (workflow « Publier Wouf » : récupère `wouf/` de la branche par défaut, relance les tests, publie ; toutes les 3 h ou à la main via `actions_run_trigger`). Après chaque fusion, déclencher ce workflow. `config.js → site.moved: true` fait basculer l’ancienne adresse (redirection sans carnet, bandeau « Transférer mon carnet » sinon).
- Branche par défaut : `claude/infirmiere-ordonnances-upload-26nl16` ; la publication (GitHub Pages) se déclenche à chaque push dessus, **après** les tests (`.github/workflows/pages.yml`). Les branches de travail passent par une pull request (le workflow « Wouf — tests » tourne dessus).
- **Aucune dépendance externe dans les pages** (audit de sécurité) : Freelance Kit utilise un CSS Tailwind compilé (`freelance/tailwind.css`, commande dans `freelance/tailwind.config.js`) et Alpine hébergé (`freelance/vendor/`) ; l’exemple alimentation héberge three.js (`exemples/alimentation/vendor/`) ; les polices sont hébergées (`assets/fonts/`, `infikit/fonts/`), jamais Google Fonts. Ne pas réintroduire de script ou de police d’un service externe. Les pages sensibles portent une politique de sécurité minimale (`<meta http-equiv="Content-Security-Policy">`). Les exports CSV neutralisent les formules (apostrophe devant `= + - @`).
- Ne jamais écrire de clé secrète dans le dépôt (aucune n'est nécessaire : PayPal par simple lien).
- Contenu santé / juridique : indicatif. Signale au propriétaire ce qui mériterait une relecture professionnelle ; n'invente jamais de tarifs d'assureurs ni de faits juridiques.
